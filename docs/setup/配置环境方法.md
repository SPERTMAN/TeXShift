# 开发环境

要求 Windows 10/11、x64 OneNote 桌面版、.NET Framework 4.8 和 `global.json` 指定的 .NET SDK。Visual Studio 可选。

```powershell
.\build.ps1 -Target Build -Configuration Debug
.\build.ps1 -Target Test -Configuration Debug
```

脚本自动恢复 NuGet 和固定版本的 MathJax。构建本身不写注册表，也不需要管理员权限。

## Debug 加载项

首次使用或仓库移动后，关闭 OneNote，在管理员 PowerShell 中注册一次：

```powershell
.\setup\Register-TeXShiftDev.ps1 -Action Register
```

注册项位于 64 位 `HKLM\Software\Classes`，OneNote Addins 项位于当前用户 HKCU。`DllSurrogate` 是 OneNote Click-to-Run 环境下的必要配置。

后续直接重新构建并重启 OneNote。DLL 路径不变，无需重新注册。状态检查无需提权：

```powershell
.\setup\Register-TeXShiftDev.ps1 -Action Status
```

Debug 和安装版使用不同的 CLSID/ProgID。两者同时注册会显示两套 Ribbon；移除 Debug 版需关闭 OneNote，并在管理员 PowerShell 中运行：

```powershell
.\setup\Register-TeXShiftDev.ps1 -Action Unregister
```

## 本地 E2E

```powershell
.\tests\TeXShift.Tests.E2E\Verify-Smoke.ps1
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe convert --input "test.md" --output ".\TestResults"
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe convert --input "test.md" --select "{first paragraph}" "{last paragraph}" --output ".\TestResults"
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe convert --page ".\TestResults\page.one" --caret "{paragraph text}" --mode ui --output ".\TestResults"
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe write-xml --markdown "Original text" --outline "Original text" --changes ".\tests\TestData\OneNoteWrites\replace-text.xml" --mode ui --output ".\TestResults\write"
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe reverse-xml --input-xml ".\TestResults\F04_Final_Page_XML_Basic_*.xml" --output ".\TestResults"
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe dump --hierarchy
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe dump --page "{page-id}" --output ".\TestResults\page.xml"
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe verify-restore --pages "{page-id-1},{page-id-2}"
```

`convert` 需要 OneNote；`reverse-xml` 可使用已有 XML 快照。两者向 stdout 输出 JSON，并以退出码表示结果。`dump` 只读取 OneNote XML，默认将原始 XML 写入 stdout。`verify-restore` 会反复关闭并重新启动 OneNote，只用于开发机上的主动检查，见 `docs/design/e2e-onenote-restore.md`。

`convert` 默认把光标放在第一段（Markdown 页面为新增的空段），即 Cursor 模式；`--caret` 指定光标所在段落，`--select` 选中一段或一个段落范围（Selection 模式），`--outline` 选中整个文本框。这三个参数互斥，段落按所含文本匹配。`--page` 在测试笔记本中重现出问题的页面，接受 `dump --page` 的 XML 或从 OneNote 导出的单页 `.one`（保留页面全部数据）。

`write-xml` 共用上述建页、选区及收尾流程，将 `--changes` 模板直接交给 OneNote，便于隔离 XML 写入问题。它跳过转换器及生产写入器的选区处理。模板中的 `{{pageId}}`、`{{outlineId}}` 分别替换为临时页和当前选中文本框的 ID；`{{oe:0}}` 按深度优先顺序引用该文本框内的段落 ID，从零计数。没有选中文本框时使用第一个文本框。

`--mode com` 保持当前前台窗口；`--mode ui` 在准备测试页前激活 OneNote，结束后恢复前台窗口。两种模式均调用 Core 转换流程；加载项按钮及弹窗由 Computer Use 手测覆盖。旧参数 `--foreground` 已移除。

`Verify-Smoke.ps1` 默认依次跑两种模式，并把光标放在后面的非空段落，覆盖活动段落被替换的场景。接受 `-Mode com`、`-InputFile test.md`、`-Configuration Release` 和 `-OutputDirectory`。任一模式失败时脚本返回非零退出码。

`convert` 在恢复、清理和释放完成后输出最终 JSON。转换成功但收尾失败返回 `6`，诊断文件写入失败返回 `7`；已有转换错误的退出码保留。`--cleanup false` 保留测试页面，仍执行恢复和释放。恢复失败时保留测试资源。

每次运行的 `F07_E2E_Run_*.json` 记录模式、启动方式、OneNote PID、原页面和测试页面 ID、各阶段耗时与错误、清理结果及退出码。`F06_Perf_*.txt` 只记录转换流程耗时。输出目录始终保留。

调试转换在调用 OneNote 前将实际写入请求保存为 `F03_Page_Changes_*.xml`（反向为 `R03_Page_Changes_*.xml`）。`write-xml` 还保存写入前的选区 XML 和 `F08_Final_Selection_*.xml`，用于比对编辑位置。
